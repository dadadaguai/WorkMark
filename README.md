# WorkMark

> 当前版本：**v0.1.0**

本地优先的个人工作记录工具，提供文档、任务段、多类型内容块、搜索、附件与收件箱。技术栈为 Vue、Flask、SQLite。

## 首次安装

需要 Python 3.10+ 和 Node.js 20 LTS 或更新的受支持 LTS 版本（含 npm）。以下命令适用于 Windows PowerShell，项目路径按实际位置调整。

```powershell
cd D:\space\WorkMark
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm.cmd ci
npm.cmd run build
cd ..
```

- 没有 `py` 命令时，用已安装的 `python` 替代 `py -3`。
- 直接调用虚拟环境 Python，无须激活环境或修改执行策略；`npm.cmd` 可避免 PowerShell 对 `npm.ps1` 的限制。
- 首次安装和构建通常需要联网；完成后核心记录功能不依赖互联网。Node.js 仅用于安装、构建和开发，日常运行不需要启动 Vite。

## 日常启动（推荐）

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m flask --app backend.main run --host 127.0.0.1 --port 8000 --no-debug --no-reload
```

保持终端运行，访问 <http://127.0.0.1:8000>。完成安装与构建后，此步骤无需联网。停止服务时按 `Ctrl+C`。

此命令关闭调试与热重载；`python run.py` 当前开启调试，不作为日常启动方式。这里仍使用 Flask 内置服务器，仅适用于本机个人使用，不用于公网或多人部署。不要监听 `0.0.0.0` 或通过端口映射开放服务。

离线不等于无需服务：关闭后端终端后不能正常保存，也不能仅双击 HTML 文件使用。固定使用同一浏览器配置与地址；`localhost`、`127.0.0.1` 和不同端口属于不同浏览器存储来源，切换地址可能看不到原有模板。

## 数据与退出

| 数据 | 保存位置/规则 |
| --- | --- |
| 文档、文件夹、任务段、收件箱、附件元数据 | 项目根目录下 `data/workmark.db` |
| 托管附件 | `data/attachments/` |
| 引用附件 | 仅保存原始路径，不复制文件；移动、删除或断开原文件所在磁盘后会失效 |
| 内容块模板 | 当前浏览器站点的 `localStorage`，不在数据库内 |

- `data` 被 Git 忽略，提交代码不会备份业务数据。更换项目目录时不要遗漏它；不同项目副本可能使用不同数据目录。
- 停止输入约 800ms 后触发自动保存。退出前确认“已保存”，再关闭页面与后端；有失败或未同步提示时先重试。
- 服务停止时，先重启服务，再在原页面重试，不要直接刷新。
- 当前没有正文草稿持久化恢复，崩溃、断电或强制结束进程可能丢失未落库输入；关闭提示不能覆盖这些情况。
- 当前没有回收站，删除文档/文件夹可能级联删除内容，不能在应用内直接恢复。
- 清理浏览器站点数据或更换浏览器可能丢失模板；备份 `data` 不包含模板和引用附件原文件。

## 手动备份与恢复

无需等待自动备份功能。建议每天使用结束后、更新程序前备份，保留多个日期版本。

1. 确认内容已保存，关闭页面，停止所有访问该数据目录的 WorkMark 后端进程。
2. 将整个 `data` 文件夹复制到项目目录之外，按日期命名。
3. 至少保留一份在另一块磁盘或外部存储中，同盘副本不能抵御磁盘故障。
4. 引用附件原文件需另行备份，长期保存重要附件优先托管上传。

SQLite 已开启 WAL。服务运行时，不要只复制 `workmark.db` 就认为备份完整。本说明采用停止服务后复制整个数据目录的方法。若以后实现在线备份，应使用 SQLite Backup API 等一致性方案，并协调备份附件。

恢复步骤：

1. 关闭页面并停止全部后端进程。
2. 先将当前 `data` 完整复制到另一处保留，避免覆盖唯一副本。
3. 用备份中的整个 `data` 替换当前数据目录，不要混入旧库的 `-wal`/`-shm` 文件或只合并部分文件。
4. 启动与备份兼容的程序版本，检查文档、搜索和托管附件。

保存重要资料前，建议在独立项目副本中实际恢复一次，确认备份可用；不要用唯一正式数据做恢复实验。

## 更新与故障排查

- 更新前保存内容、停止后端并备份 `data`；不要直接删除整个旧项目目录。
- 依赖变化时重新安装；前端变化时在 `frontend` 执行 `npm.cmd ci`、`npm.cmd run build`，然后重启后端并刷新页面。
- 数据库迁移后，回退旧程序应同时使用对应数据备份，不要直接让旧代码打开迁移后的库。
- 依赖缺失：用启动时同一个虚拟环境 Python 执行 `-m pip install -r requirements.txt`。
- 页面打不开：检查后端是否运行、终端是否报错、地址和端口是否正确。
- 端口占用：先检查是否已有 WorkMark 服务，避免重复启动；改端口会改变浏览器站点存储来源。
- 首页 404 或前端未更新：确认 `frontend/dist/index.html` 存在，重新构建并重启后端；构建目录在后端启动时检测。
- 保存失败：保持页面打开，检查或重启后端后重试。当前请求无统一超时保障，长时间无响应时检查后端日志。
- 引用附件打不开：检查原始路径和磁盘连接；移动原文件不会自动更新引用。

## 开发模式（非日常必需）

在根目录运行 `.\.venv\Scripts\python.exe run.py`；另开终端，在 `frontend` 执行 `npm.cmd run dev`。访问 Vite 显示的地址（通常为 `http://localhost:5173`），其 `/api` 代理到本机 8000 端口。开发模式有调试/热重载行为，不建议边改代码边编辑重要资料。
